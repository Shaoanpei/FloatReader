# FloatReader · 悬浮阅读器

上班摸鱼用的桌面小浏览器：**窗口永远置顶、可拖动可缩放、背景完全透明、只显示网页里的文字**。

只保留正文，图片、广告、侧栏、导航全部丢掉，看起来就像文字直接浮在桌面上。

## 安装

```powershell
pip install PySide6 beautifulsoup4 fonttools brotli
```

- `PySide6`：界面与富文本渲染
- `beautifulsoup4`：解析网页、抽正文
- `fonttools` + `brotli`：还原字体反爬（woff2 解压必须要 brotli，缺了会报「字体还原失败」）

`fonttools` 用于还原使用「字体反爬」的站点（见下方说明），不装也能跑，只是这类站会显示成生僻字。

## 运行

双击 `run.bat`，或：

```powershell
python reader.py
```

首次启动会显示操作引导，按 `Ctrl+L` 输入小说网址即可。

**每次启动都从引导页开始**，不会自动打开上次的页面。想接着上次的看，可以从右键菜单
→「书签」里点；或者直接 `Ctrl+L` 输地址。

## 打包成 exe（脱离 Python 运行）

双击 `build.bat`，等 1~3 分钟（脚本会自动装 PyInstaller、清理旧产物、打包、再建桌面快捷方式）：

```
dist\FloatReader\
├── FloatReader.exe      ← 双击这个（或桌面快捷方式）
├── _internal\           ← 依赖库，必须和 exe 放一起
└── config.json          ← 首次运行自动生成
```

**注意**

- 分发时要拷**整个 `FloatReader` 文件夹**，只拷 exe 会启动失败
- 体积约 130 MB（PySide6 占大头），已排除 QtWebEngine / QtQuick / QtMultimedia / QtPdf / QtTest 等无用模块
- `config.json` 生成在 **exe 同目录**，所以整个文件夹可以搬到别的电脑直接用
- 用 onedir 而不是单文件（onefile）：单文件每次启动都要把 130 MB 解压到临时目录，启动慢，退出时还容易弹「Failed to remove temporary directory」警告

鼠标操作：

- **鼠标中键拖动**正文任意位置即可移动窗口（最顺手的方式）
- 也可以按住窗口**顶部 18px 的细条**拖动（鼠标移上去会浮出一根短横线）
- **右下角**三个小方块处拖动可改变窗口大小
- **右键**任意位置弹出功能菜单

滚动条是隐藏的；鼠标停在顶部细条或右下角手柄上时，滚轮也能翻页。

> 窗口被隐藏后（不占任务栏），窗口内的快捷键会全部失效。恢复方式有两个：
> 全局热键 `Ctrl+Alt+H`，或右键系统托盘图标 →「显示 / 隐藏」。
> 隐藏时会弹一个托盘气泡提醒；`Ctrl+Alt+H` 只在隐藏期间注册，平时不会占着这个组合键。

## 工作原理与取舍

程序不是 Chromium 浏览器，而是：

1. 用 `QNetworkAccessManager` 下载网页 HTML
2. 用 BeautifulSoup 去掉脚本、图片、导航、广告，找出正文容器
   （`#content`、`#chaptercontent`、`article` 等常见小说站/新闻站结构）
3. 把正文交给 Qt 富文本控件渲染，背景设为全透明

**字体反爬还原**：不少小说站会把正文里的字换成 CJK 扩展区的生僻字码点
（页面里写作 `&#169595;` 这种数字实体），再用 `@font-face` 自定义字体把这些码点
画成正常汉字，就是为了防爬。直接抓 HTML 只会得到一堆生僻字。

本程序会用同样的方式破：从页面找到它引用的样式表 → 找到 webfont → 读字体的
cmap 和字形名（这类字体通常保留了 `uni95E8` 这样的原始 Unicode 名字）→ 把密文
逐字映射回明文。字体每次请求都会重新生成，所以必须和页面在同一轮请求里取。

要是遇到的站点用的是别的混淆方式（比如直接换成形近字），那就还原不了。

另外，程序会采样窗口下方真实屏幕的亮度，自动把文字切成深色或浅色，所以不管壁纸是深是浅、
窗口拖到哪个程序上面，字都基本看得清。

如果背景实在太花，可以按 `Ctrl+O` 打开一圈细反色描边（会有“空心字”的感觉，按需使用，
默认是关闭的实心字）。

这样做的原因：Chromium 内核在 Windows 上做不出可靠的"背景透明只留文字"，
而 Qt 自绘文本的透明是原生能力，且秒开、内存小、无 GPU 占用。

**代价**：不支持靠 JavaScript 动态渲染的页面（在线小说站、新闻站基本不受影响）。
如果某个页面抽不到正文，程序会直接把整页文字倒出来。

## 挂了 VPN 后打不开？

有些站（尤其是挂在 Cloudflare 后面的中文小说站）会把 VPN 的出口 IP 判为可疑，
返回 `403` 加一个 `Just a moment...` 的 JS 挑战页。这种页面必须执行 JavaScript
才能过，而本程序只是纯 HTTP 抓取，所以会一直卡在「打不开」。

程序对此做了自动处理：

1. 先按**系统代理**发请求（与浏览器一致，需要翻墙的站照样能开）
2. 一旦被挑战页拦住，立刻改走**直连**重试一次
3. 成功后按域名记住哪条通道能通，之后同一站点直接走对的那条，不会每次都双重请求

如果某个站反而必须走代理，或者你想让所有请求都绕开 VPN：右键菜单 →
「网络通道」→ 选 **跟随系统代理（默认）** 或 **总是直连（绕过 VPN）**。
选择会存进 `config.json` 的 `net_direct` 字段。

## 预加载下一章

每打开一页，程序会在**后台线程**里把「下一章 / 下一节 / 下一页」提前抓下来、抽好正文，
**顺手把字体反爬也解密完**，存进内存缓存（保留最近 4 页）。

这样按 `Ctrl+→` 或点「下一章」时是直接从内存渲染，不再等网络；命中缓存时右上角会闪一下
「⚡ 已预加载」。新页面打开后又会继续预取它的下一章，形成链式预取。

- 预取失败不会影响正常阅读（真正点的时候会重新加载）
- 不想要额外流量的话，按 `Ctrl+P` 关掉

## 书签

- `Ctrl+B`：收藏当前页；再按一次取消收藏
- 右键菜单 → **书签** 子菜单，点条目直接打开（最近收藏的排最前）
- **右键某个书签条目 → 弹出「删除」确认菜单 → 左键点它才真正删除**
- 托盘图标右键也有同一份书签菜单
- 子菜单底部有「清空书签」
- 最多保留 30 条，存在 `config.json` 的 `bookmarks` 字段里

## 本地 txt

按 `Ctrl+F`（或右键「打开本地文件…」）选一个 txt，不用联网。

- 每 600 行一页，文首/文末有「上一页 / 下一页」，也可以用 `Ctrl+→`
- 标题会显示页码范围，例如 `sample.txt    第 601-1200 行 / 共 5231 行`
- **书签会记下文件路径 + 当前行号**：`Ctrl+B` 收藏当前位置；之后在书签里点它，
  会直接打开该文件并跳到那一行
- 同一个文件再次收藏会**更新位置**（当成阅读进度用）；位置相同（±2 行内）则取消书签

## 链接与按钮

程序不是浏览器，图片、按钮、下拉框、需要 JavaScript 的交互都不存在。

但**超链接是保留的**：

- 正文里的链接（包括**目录页的章节列表**）原样保留，点击即可打开
- 目录页会被自动识别成"章节列表"模式，每行一个可点的章节链接
- 程序还会把「下一章 / 下一页 / 目录 / 返回书页」提到**标题下方**和**文末**，
  方便直接翻章；也可以按 `Ctrl+→`
- 如果某个站的「下一章」是 JS 按钮，程序会读页面里的 `<link rel="next">` 当兜底
